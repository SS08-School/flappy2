# Flappy Bird — v1.3 reference build

Flappy Bird v1.3 movement and graphics based on the [supplied gameplay reference](https://www.youtube.com/watch?v=8nJhk_u4krI), using the uploaded official sprite sheet and supplied sound effects. The menu and every run independently choose an official yellow, blue or red bird. Difficulty level 3 randomly selects frame-traced video chunks. Recording watermarks are omitted.

## Run

With Node.js 18 or newer:

```sh
npm start
```

Open **http://localhost:3000**. `npm run dev` restarts the server on source changes. There are no package dependencies.

## Controls

Select Play, then click or tap anywhere, including the black bars, or press Space/Up/W to flap. **Escape does nothing and never resets the run.** Rate and leaderboard buttons are visual placeholders, as requested. Sound unlocks on interaction; the idle bird animation is silent.

Play, clicks and taps never request browser fullscreen. The game fits the current browser window and also supports manually selected fullscreen. The Home Screen manifest uses fullscreen without locking orientation; iOS standalone metadata is included. App icons are nearest-neighbor crops of the uploaded bird sprite over its original sky color. Selection, scrolling, drag, callouts and Tab navigation remain disabled.

A visible physical press restores the game’s focus state even if the browser sends its focus event later. Ready-screen taps during the transition are retained and applied when the fade finishes. Flap impulses still apply inside the input handler at the event timestamp, independent of render rate.

## Reference measurements

The game uses the same **384-native-pixel-high gameplay world** and ground at y=336 on every device. Only horizontal camera framing and a single uniform display scale change. The frame is capped at **16:10 in either orientation**, with centered bars when a display is wider or taller. Phones support both portrait and landscape; rotation refits the screen without pausing, restarting, moving the bird vertically, or refitting pipe geometry. Visible world width ranges from 240 to 614.4 native pixels. The **288 × 384** reference still defines all sprite and UI measurements; artwork is never stretched along one axis.

Continue development on `main`. The `Flappy-Bird-Original-Mobile-Version-11-23-2026` branch preserves the original mobile version and must remain unchanged.

| Element | Native measurement |
| --- | --- |
| Bird / pipe width | 34 × 24 / 52 px |
| Foreground ground strip | 48 px; ground at y=336 |
| Pipe speed / spacing / gap | 120 px/s / 156 px / 100 px |
| First pipe | Starts offscreen on the first flap, 426.48 native px ahead of the bird, based on the maximum 16:10 world |
| Simulation | 60 Hz steps, with fractional steps at exact input times |
| Rendering | Display refresh rate, capped at 240 FPS; fractional-step bird/pipe previews and continuous ground scrolling |
| Flap impulse / gravity | −330 px/s / 1100 px/s², fitted from the recorded flight arc |
| Large score | Centered at y=18, official 24 × 36 glyphs |
| Result score | Separate official 14 × 20 glyphs (10 px wide for 1) |
| Title / Ready / Game Over | Native y=86 / 84 / 68 |
| Result card | Native x=25, y=130 including its shadow |
| Buttons | Native x=20 and 152, y=276 |

The skyline is stationary; ground and pipes move at the same speed. Day and night backgrounds use matching interior sections of the uploaded atlas with a 22-pixel overlap, so clouds, buildings and bushes join seamlessly without altering the artwork. The menu is permanently daytime, with an independent day/night choice for every run, including the first. The title includes the original Rate, Play, leaderboard and copyright graphics. All visible words and digits come from the sheet.

The ground scroll wraps at the atlas's 24-pixel pattern repeat, overlapping matching repeats in wider views to prevent seams. Touching the top edge ends control and triggers the hit/death fall, just like a pipe collision.

The opening pipe has no spawn delay. Its initial distance is fixed using the 16:10 view, placing it exactly outside that view and farther offscreen in narrower windows. The first point arrives about 3.67 seconds into the run at every supported aspect ratio; later pipes follow every 1.3 seconds. Following pipes are queued a full spacing ahead of the shared start edge, so they always exist before entering the visible screen. Resizing preserves each pipe's distance from the bird.

## Difficulty levels

**Level 1** is the unchanged original pipe layout: fixed 120 px/s travel, 156 px spacing and 100 px gaps. Classic heights are sampled continuously across the original 100–236-pixel center range, with bounded resampling against the last two heights to reduce near-repeats and alternating patterns. **Level 3** activates at score **5** for testing (`LEVEL3_TEST_SCORE` in `public/difficulty.mjs`). Level 2 and levels after 3 are not implemented yet.

Level 3 always opens with a flat, short three-pair upright tunnel, using the normal 55-pixel tunnel pitch. Its height is deliberately offset from the last classic gate, with a short 172-pixel transition spacing. The catalog contains **21 formations** measured against complete sequences from the [High Score 999 video](https://www.youtube.com/watch?v=YHH2101OFfI), including the rising trio followed by uneven fixed gates (15–18 s), the stationary roof and moving floor groups (18–23 s), and the diagonal tunnel with its downward overlay exit and opposing floor tips (48–53 s). Every roof formation follows a six-column enclosed descending approach: its uneven enclosed openings descend by 70 native pixels overall and feed directly into the rising floor bank. The approach has independently irregular roof and floor tips instead of six consecutive stair steps. A short flap-release space avoids an empty handoff. The roof silhouette and the returning pair with synchronized endpoints are retained; intentional three-pipe groups share their speed and phase, while independent gates retain varied speeds.

Ordinary flat and high/low tunnels contain three pipe pairs, while the irregular short tunnels contain four. The high/low formations change direction instead of making miniature staircases. Irregular tunnel floors are mostly uneven; only one of four profiles contains a brief two-step floor run. Roofs use independently uneven heights with small random offsets and never form staircases. Their gaps vary, with at least 108 native pixels of clearance, instead of keeping both walls parallel. Rare long variants keep nine columns plus the downward overlay exit. They include an approximately 100-pixel floor drop, with the roof following two columns later to leave a usable turning window; the reverse variant opens the roof two columns before a similarly large floor rise. Small uneven changes interrupt the ledge's surrounding steps. The geometry stays inside the ceiling and ground limits without flattening the route. All ordinary columns use the existing 55-pixel pipe pitch, and height connectors align the incoming passage.

Most vertical pipes use constant-speed rails, with predictable reversals and full travel preserved during ground fitting. The roof formation uses a staged ascent: the leading trio rises steadily from offscreen and stays extended. Its three posts share the same speed around 12 native px/s, start time and endpoint. The upright rising trio likewise shares one 42 native px/s rail, including both reversal times, so neither trio drifts out of alignment. The following pair is already rising when it first becomes visible, with synchronized start, peak and low-endpoint times. The right pipe travels farther and therefore moves faster on both legs: about 58 versus 50 px/s upward and 84 versus 72 px/s downward in the baseline profile. Both reverse together without holding at the peak. Three bounded profiles vary the speeds and timing while preserving those roles. A fixed third floor pipe follows the returning pair; their final caps form three regularly spaced short saw teeth, stepping upward by 12 native pixels per pipe. The stationary roof consists of one long leading diagonal pipe, the restored intermediate shaft connecting it to the bank, and four pipes forming a clean stepped slope. The recording’s manual initial pause is excluded from the motion timing. All roof variants share a cooldown of six complete intervening sections; brief rising-floor interludes do not shorten it. Relative scroll-compensated positions are checked against the recording.

A separate **descending-pursuit** formation follows the fast downward stroke in the restored 32–34-second clip: one full gate travels through 152 native pixels at approximately 210 px/s. It can appear only after five final chunks, and seven complete chunks must pass before another occurrence. Its full lower cap remains visible even at the bottom of the stroke.

The guide and actual moving entry share the same center, with ten native pixels of extra space above and below the guide. The vertical rail spans 128 pixels, reserving more room for the player while keeping both caps visible. This authored lead-in is not widened around the moving pipe’s neutral pose. Its gap moves downward throughout the full crossing instead of reversing while the bird is inside. It is excluded from the first five chunks and has a seven-chunk repeat cooldown. Additional short shaky formations remain disabled. The director retains five-chunk repeat exclusion, avoids nearby matching motifs where possible, and excludes left-moving sections and the fast downward passage from the first five level 3 chunks. Occasional ten-pair long tunnel variants are scheduled roughly every 7–9 chunks, with reserved roof approaches sometimes shifting the actual interval. Ordinary sections continue with the same three-native-pixel gap used inside tunnels, measured after the full visible shaft footprint. Long shafts extend using alternating reflected crops of the official shaft, joining matching end rows with no stretched single-row splice. All upper caps retain at least 12 native pixels of ceiling clearance across their complete movement. Lower pipes retain the full 26-pixel cap and at least 24 native shaft pixels above ground; the following roof pair may return to eight shaft pixels and the two fast vertical obstacles may approach within two shaft pixels. Static adjustments follow the shaft direction. Straight stationary banks share their floor and roof corrections, preserving equal-length tips and intentionally varied silhouettes instead of clamping individual pipes into isolated outliers. Moving rails retain their full configured distance and speed, and these bounds do not change when the display rotates. The level switches on the fifth point. Level 3 is queued ahead of time after the fifth classic gate, with a short 172-pixel transition spacing. The first three-pair tunnel has a clear height change from the last classic opening and contains no diagonal or moving posts. The switch does not replace visible obstacles or restart the spawn clock. Level 3's measured horizontal travel is 118 native px/s. Rendering, collisions and scoring share the same transforms and freeze on impact. All images remain native-width crops of the uploaded green pipes; no other graphics or controls are added.

The source timestamps in `public/level3-chunks.mjs` identify each reference behavior. Geometry is aligned and shortened for this project, with playability corrections, rather than presented as pixel-exact recovered game code. The earlier warped perspective samples are excluded. The reference's 400-pixel ground is aligned to the fixed y=336 gameplay ground without stretching sprites.

Pipe translations align to physical canvas pixels after viewport scaling, keeping nearest-neighbor sprite edges and shading from shimmering as fractional offsets change. This rounds by at most half a device pixel and retains the original collision coordinates.

Rendering uses `requestAnimationFrame` with a 240 FPS ceiling. Lower-refresh displays run at their available rate. Drawing previews the unsimulated fraction of the next fixed step using the current flap velocity, instead of blending past positions a full step behind. The preview stays within the screen and never changes physics, collision tests, scoring or difficulty. Keyboard and pointer inputs apply immediately and appear on the next displayed frame. Tab and Shift+Tab are prevented from moving focus or triggering a game action; the canvas and Play button are removed from the Tab order. The browser and monitor determine the actual achievable frame rate.

Input handlers use the browser event’s press timestamp when available, so queued input is not treated as extra falling time before the flap. Stale timestamps are clamped to the last committed state, and foreign-clock timestamps safely fall back to the current time. Handlers synchronize the simulation to that event time, commit any pending fraction with the old velocity, then apply the full flap impulse immediately. Pre-key time cannot weaken a new flap after a slow frame. Fractional steps compose to the same original 60 Hz flight arc; the render limiter only controls drawing. Rendering samples the current clock inside the animation callback, so an older queued callback timestamp cannot delay a newly handled flap or the first frame after focus returns. Small timestamp jitter is tolerated without dropping a refresh. Hidden tabs and unfocused windows pause without building up catch-up time. There is no debounce or intentional jump delay; browser scheduling and hardware still determine physical input-to-display latency.

Obstacle fitting runs in a module Web Worker on supported browsers. Input handlers and animation frames only request and collect prepared geometry, several seconds before it reaches the bird. Delayed replies are translated by the exact world distance and camera shift since the request, preserving positions and movement phase through rotation. Replay rejects stale replies from the previous run. Browsers without working module workers retain the existing generator as a fallback. No fullscreen request is made by gameplay input. Manual fullscreen/F11 and display-size changes reset the simulation clock and render deadline after the browser replaces its canvas surface, excluding the resize stall from flight timing. The game requests low-latency canvas presentation where supported.

The official NEW badge already matches the supplied screenshot at native (166, 189), two pixels left of BEST. It is shown only after beating the previous best, not tying it.

Screen changes fade through black. The Game Over heading, slide-up card, score count-up, medal and buttons appear in the reference order. Numeric timings are measured from a compressed 30 fps recording, so they are approximations rather than recovered original source constants.

The additional [bird-animation reference](https://www.youtube.com/watch?v=1vo4HPystfM) shows a slower idle cycle (14 recorded frames, about 0.467 s) and a faster playing cycle (6 frames, 0.2 s). A tap restarts the raised-wing pose; a steep descent holds the middle wing. Idle bobbing repeats every 0.75 seconds and travels about eight native pixels peak to peak. These use the corresponding three official frames for each selected bird color; the recording supplies timing measurements only. The descent threshold and bob amplitude are fitted estimates from compressed footage. Collision capture uses the incoming flight angle and retains an already downward rendered pose. A flap rejected during pending collision motion cannot restart the flap presentation; upward impacts still retain their raised pose. The existing flash, rotation and result timings are unchanged.

Each actual flap plays wing, each passed pipe plays point, and a collision plays hit once. Pipe collisions add the falling death sound 0.2 seconds later; direct ground crashes only play hit. Play/replay transitions, the Game Over heading and the scorecard each play swoosh. The supplied files are copied unchanged into `public/assets/audio/`; playback skips leading padding, including 120 ms in the point recording. Web Audio preloads and decodes the files, supports overlapping flaps, and cancels active/pending sounds on replay. Missing audio support does not block gameplay.

The medal glimmer follows the supplied `17-57-55` capture: small, medium, large, medium, small official sparkle frames at 10 Hz. Each half-second pulse stays at one random position, then jumps to a new position around the medal. It starts with the awarded medal and is omitted for reduced motion.

BEST persists silently in browser local storage. There are no accounts, custom dialogs, powerups, unlocks, extra lives, downloaded graphics or fonts. Existing ignored database files remain untouched.
